## 概要

乱数はUnity標準のクラスが用意されていますが、各所で直接参照することはせず、インタフェース経由でアクセスするようにしています。

|                        | 直接参照   | インタフェース経由                           |
| ---------------------- | ---------- | -------------------------------------------- |
| 乱数アルゴリズムの変更 | 面倒くさい | 実装クラスの改修、或いは差し替えで対応できる |
| 特定条件時のテスト     | 相当難しい | スタブで対応できる                           |

## 準備

乱数を使いたい処理が定義されているレイヤーにインタフェースを定義します。

```csharp
namespace MyGame.Domain
{
    /// <summary>
    /// 乱数生成器のインターフェース
    /// </summary>
    public interface IRandom
    {
        /// <summary>
        /// min 以上 maxExclusive 未満の整数乱数を返します。
        /// </summary>
        int Next(int min, int maxExclusive);

        ... // 必要なメソッドを定義する（float版など）
    }
}

namespace MyGame.Domain
{
    /// <summary>
    /// 乱数生成器のファクトリインターフェース
    /// </summary>
    public interface IRandomFactory
    {
        /// <summary>
        /// 乱数生成器を取得します。
        /// </summary>
        IRandom Get();
    }
}
```

## プロダクト用の乱数処理

プロダクト用の乱数の生成処理の実装を、Infrastructure層で定義します。

![プロダクト用](https://raw.githubusercontent.com/ushibutatory/tech-images/refs/heads/main/articles/4624baa67a9acc/random-prod.png)

```csharp
namespace MyGame.Infrastructure.Adapters.Domain
{
    /// <summary>
    /// シード値を持つ乱数生成器
    /// </summary>
    public class SeededRandom : IRandom
    {
        private readonly System.Random _random = null!;

        /// <summary>
        /// シード値
        /// </summary>
        public int Seed { get; private set; }

        public SeededRandom(int seed)
        {
            Seed = seed;

            _random = new System.Random(seed);
        }

        /// <inheritdoc/>
        public int Next(int min, int maxExclusive) => _random.Next(min, maxExclusive);
    }
}

namespace MyGame.Infrastructure.Adapters.Domain
{
    public class SeededRandomFactory : IRandomFactory
    {
        private IRandom _random = null!;

        public IRandom Get() => _random ??= _New();

        private IRandom _New()
        {
            // IMPORTANT: プロダクト用の乱数シードはここ
            var seed = System.Environment.TickCount;

            return new SeededRandom(seed);
        }
    }
}
```

上記はシードを使った標準のRandomクラスを使っていますが、乱数テーブルを内部的に持つ、独自の生成アルゴリズムを使う、といったクラスへの差し替えも容易になります。

## テスト用の乱数処理

テスト用のスタブを用意します。

![テスト用](https://raw.githubusercontent.com/ushibutatory/tech-images/refs/heads/main/articles/4624baa67a9acc/random-test.png)

```csharp
namespace MyGame.Domain.Tests._Stubs
{
    public class StubRandom : IRandom
    {
        private readonly int _value;

        public StubRandom(int value = 0)
        {
            _value = value;
        }

        // 指定した値をそのまま返すだけ
        public int Next(int min, int maxExclusive) => _value;
    }
}

namespace MyGame.Domain.Tests._Stubs
{
    public class StubRandomFactory : IRandomFactory
    {
        private readonly IRandom _random;

        public StubRandomFactory(int value = 0)
        {
            _random = new StubRandom(value);
        }

        public IRandom Get() => _random;
    }
}
```

テストケース側では例えば以下のように使用します。
（雑な例で恐縮ですが）

```csharp
namespace MyGame.Domain.Tests
{
    public class SomeTest
    {
        [Test]
        public void 同じRandomなら常に同じ結果になる()
        {
            // 常に同じ値を返す乱数
            var randomFactory = new StubRandomFactory(x);

            // 入力に対して出力を返すドメインロジック
            var domainFunction = new DomainFunction(randomFactory);

            var value1 = domainFunction.Execute();
            var value2 = domainFunction.Execute();
            Assert.That(value1, Is.EqualTo(value2));
        }
    }
}
```

## 所感

時計（`SysDate`）も同じようにインタフェースを分けておくと、特定日時のテストなどがしやすくなります。

乱数や時計など、本来はシステムの「外」にある環境依存なのに、何故かハードコードされがちなイメージがあります。
